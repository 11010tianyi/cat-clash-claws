# 猫猫对战（Cat Clash Claws）审阅报告

审阅对象：`11010tianyi/cat-clash-claws`，基线 `main` @ `f1decc0`（README 标为 v2.3）。  
本轮只审阅，不改玩法。结论分两类：

- **已证实**：本地 `python3 -m http.server` 打开页面后，用无头 Chrome 调用真实 `game` / `CatAI` / `BattleSystem` 跑过，或单看控制流就能判定。
- **猜测**：由代码外推，没有在对应设备或协议上跑完。

验证范围：菜单加载、人机对战初始化、近战一击、技能空放、4 秒人机走位、左右冲撞、竹海伤害数字坐标、打耗子缩放矩阵、抢食物负分、双倒地结算、能量按帧恢复。未在真机触屏上点按，也未用 `file://` 打开页面。

---

## 一句话定位

这是一款纯前端 Canvas 的本地双猫对战：实时走位 + 三局两胜，外加「抢食物」「打耗子」两个 90 秒计分模式。可爱和系统数量都够，但人机对战目前打不起来，冲撞和放大地图的表现会直接违背界面上写的规则。

## 玩法摘要

入口是 `index.html`。`js/game.js` 的 `CatClashGame` 持有主循环（`gameLoop` → `update` → `render`），`js/battle.js` 管三局两胜，`js/cat.js` 管角色数值、普攻、暗器、技能和受击，`js/ai.js` 只操控茉莉，`js/ui.js` 管 DOM 血条和飘字，`js/minigames.js` 管耗子，`js/maps.js` + `js/scenery.js` + `js/photo-scenes.js` 管三张地图和背景。

玩家实际会碰到的规则，以战斗中「?」帮助（`index.html`）和代码为准，而不是 README / `.trae/documents/PRD.md`（这两份已经落后）：

| 模式 | 怎么赢 | 关键模块 |
| --- | --- | --- |
| 猫猫对战 | 先把对方血量打到 0 拿下小局，先拿 2 局赢 | `BattleSystem.checkWinCondition` |
| 抢食物 | 90 秒内分数高。猫草：黑茶 −2 / 茉莉 +2；塑料袋相反；普通食物 +1 | `getFoodRushScoreDelta` |
| 打耗子 | 90 秒内暗器击杀积分高。反噬鼠被打中反扣 10 血 | `checkProjectileRatCollisions` |

对战操作：黑茶 WASD / J 攻击 / U 暗器 / K 防御 / L 技能；茉莉方向键 / 小键盘 1、0、2、3。连按两下快移（扣 8 能量），连按三下冲撞（宣传为 6–15 伤害、60 秒冷却）。技能实际消耗 **35** 能量（`Cat.useSkill`），不是 README 写的 50。防御对暗器是直接删除投射物（100% 格挡）；对近战是随机减 12%–40%（`mitigateDamageWhileDefending`），不是 README 写的减半。

默认角色是照片立绘（`characterStyle = 'photo'`，`images/black-tea.png`、`images/white-Jasmine.png`），默认地图樱花庭院。竹海 `scale: 2`、峡谷 `scale: 3` 会把逻辑世界放大，再用 `renderScale = 1/scale` 整张缩回视口，摄像机固定在 `(0, 0)`（`updateCamera`）。

## Bug 列表

### P0

**1. 人机对战接不住战：远距离只会挪步，4 秒只走近约 21 像素，攻击 0 次**

- 状态：**已证实**（中等难度、樱花庭院、两猫相距约 840px，真实时钟跑 4 秒）。
- 位置：`js/ai.js` `makeDecision`、`moveTowardsTarget`；步长来自 `js/game.js` 的 `NORMAL_MOVE_SPEED = 3`。
- 决策顺序把优先级写了又覆盖掉。距离 > 300 时，函数末尾无条件 `action = 'approach'`，把前面的暗器决策盖掉。距离 800 时，中等和大师各抽样 300 次，**全部是 `approach`**。暗器窗口只剩大师难度的 220–480px；中等难度只在 280–300 这 20px 里有机会丢暗器。
- 走近也不是持续移动。`executeAction` 用 `setTimeout(reactionDelay)` 后调用一次 `moveCat('shiro', ±3, ±3)`。中等难度反应 400ms、决策冷却 40 帧。实测 4 秒内茉莉 `targetX` 只变化 **−21**，`fireProjectile` / `attack` / `skill` **0 次**，距离仍约 840。同一套循环里玩家按住方向键约 720px/4 秒（240 帧 × 3）。
- 后果：中等难度要先走出大约 `(出生间距 − 220) / 5px/s`。按这次实测的约 5px/s，从 840px 走到近战 220px 要两分钟量级，期间 AI 不攻击。简单难度还有 50% 概率把决策改成乱走（`Math.random() > 0.5`），更慢。
- 猜测：完整打完三局会变成「玩家单方面输出，AI 在远处空走」。没有把一局放到血量归零，所以时长是外推。

**2. 一次冲撞可以结算多次，击退方向和冲撞方向无关**

- 状态：**已证实**。`updateRush`（`js/game.js`）在 `dist < 100` 时每帧调用 `takeDamage`，没有「本段冲撞已命中」标记。击退用的是两猫中心点的左右关系，不是 `rush.direction`。
- 实测（樱花、血量 100、`dodgeChance` 置 0 之前的默认冲撞伤害）：
  - 向左冲：命中 **2** 次，茉莉血量 **100 → 74**（约 26，而不是帮助写的 6–15），人在左边缘 `x≈70`，茉莉被送到 **`x≈1593`（右侧）**。
  - 向右冲：命中 1 次，血量到 92，茉莉出现在 **左侧 `x≈35`**。
- 原因：第一下把对方放到某一侧边缘后，`takeDamage` 再沿 x 推 25px，中心点左右对调，下一帧又按新的左右关系扔到对面边缘。帮助文案（`index.html`）和 README 都写「沿该方向撞飞、6–15 伤害」。
- 猜测：若两猫在边缘持续重叠，循环会按帧继续扣 6–15，直到冲撞 500ms 结束或被弹开。这次几何下被弹到对面后只打中 2 次，没有打出「一帧秒杀」，但守卫本身不存在。

### P1

**3. 近战命中仍播放暗器音效**

- 状态：**已证实**。`attackCat` 把 `processAttack` 的返回值（攻击结果对象）拿去和数字比：`if (damage > 0)`。对象转成数字是 `NaN`，条件恒为假，于是走 `else` 里的 `playProjectileSound()`。
- 实测：近战一击血量 **100 → 96**，能量 **80 → 83**（命中 +3 是对的），同时暗器音效计数 **+1**。
- 位置：`js/game.js` `attackCat`。

**4. 技能打空仍扣 35 能量和 180 帧冷却，并且没有「落空」日志**

- 状态：**已证实**。`Cat.useSkill` 先扣能量、上冷却，再测距离；超距返回 `{ type: 'miss' }`。`BattleSystem.processSkill` 只处理 `damage_heal` / `heal_only` / `damage` / `buff`，`miss` 是真值但没有任何分支，不会写「技能落空」。
- 实测：能量 **100 → 65**，`skillCooldown = 180`，返回类型 `miss`，`battleLog` 末尾没有落空文案。
- 位置：`js/cat.js` `useSkill`，`js/battle.js` `processSkill`。

**5. 技能必定吃 1.35 倍「暴击」，和 20% 暴击不是同一条规则**

- 状态：**已证实（代码路径 + 抽样）**。`useSkill` 调用 `calculateDamage(..., true)`，第三个参数名叫 `isCritical`，两个角色都写死 `true`。同一攻击力抽样：强制暴击约 **16–25**，不暴击约 **12–19**。普攻的暴击仍是 `critChance = 0.2`。
- 位置：`js/cat.js` `useSkill`、`calculateDamage`。

**6. 茉莉的技能名、AI 判断和实际效果是三套东西**

- 状态：**已证实**。
  - 代码技能名：黑茶「利爪突袭」、茉莉「治愈光波」（`KuroCat` / `ShiroCat`）。
  - `shiro.skillEffect === 'defend'`，所以 `CatAI` 只在血量 < 50% 时把技能当高优先级；但 `useSkill` 对两只猫都只返回 `damage` 或 `miss`，没有治疗、没有加防。
  - 画面是黑茶丢便便、茉莉猫爪（`drawSkillEffects`）。帮助弹层写的是「丢便便」「猫爪拍击」。README / PRD 写的是「暗影爆发」「神圣光芒」（还带 15% 治疗）。
- 玩家按 L / 小键盘 3 放出的东西，和血条旁不会出现的技能名、和 AI 的「该不该奶」判断，互相不一致。

**7. 竹海 / 峡谷上，伤害数字和对话用的是世界坐标，不是屏幕坐标**

- 状态：**已证实**。`UIManager.showDamage` / `showDialog`（`js/ui.js`）用 `cat.x - camera.x`，没有乘 `renderScale`。摄像机又恒为 0。
- 竹海实测：`renderScale = 0.5`，猫在世界 x=1000（屏幕上约 **500px**），飘字 `left` 却是 **1080px**。峡谷 `renderScale ≈ 0.333`、世界宽约 3 倍视口，飘字会直接出屏。
- 樱花（scale 1）不受影响。

**8. 打耗子在放大地图上被缩放了两次，位置和大小都错**

- 状态：**已证实**。`render()` 已经 `scale(renderScale)`，`renderRats()` 里又 scale 一次。竹海实测 `ctx.getTransform().a === 0.25`，正确值应是 `0.5`。樱花 scale 为 1，看起来正常，所以默认地图发现不了。
- 位置：`js/game.js` `render` 与 `renderRats`。

**9. 「隐身鼠」几乎不透明**

- 状态：**已证实（常量 + 绘制公式）**。`js/minigames.js` 里 `RAT_ALPHA_BASE = 0.92`，`RAT_ALPHA_STEALTH_MIN = 0.88`。隐身只在 0.88 和 0.92 之间用正弦晃 0.04。README 写的「半透明、容易漏掉」在画面上不成立。

**10. 双方都倒下时，整场被判平局，当前小局胜场不加**

- 状态：**已证实**。`checkWinCondition`：有猫处于 `isDying` 就直接返回；两边都 `isDead` 时调用 `onBattleEnd(null)`，不走「先死的人赢下这一局」。
- 实测：事先 `roundWins = { kuro: 1, shiro: 0 }`，双倒地后胜场仍是 1:0，回调参数是 `null`（结果页标题会是「平局」）。
- 连带问题：死亡动画 2200ms 内 `isDead` 仍为 false，`isBattleActive` 要等动画结束才在 `checkWinCondition` 里关掉。这段时间投射物和冲撞还能把另一方补死，于是本来要记的小局胜利变成整场平局。位置：`js/cat.js` `beginDeathAnimation`，`js/battle.js` `checkWinCondition`，`js/game.js` `checkProjectileCollisions`（不看 `isBattleActive`）。

**11. 打耗子的反噬可以把猫打死，死后不能动，模式却继续计时**

- 状态：**已证实（代码）**。`initTargetMode` 把 `battleSystem` 设为 `null`。反噬走 `attacker.takeDamage(10)`，血量到 0 会 `beginDeathAnimation`。`moveCat` / `canStartAction` 在 `isDead` 后直接返回。`endMinigame` 只比较分数，不复活。
- 猜测：90 秒里被反噬鼠打死的一方会空等结算。没有在完整 90 秒里打出这个结局，但扣血和死亡入口是同一条 `takeDamage`。

**12. 抢食物的扣分用伤害飘字，血量其实不变**

- 状态：**已证实**。猫草给黑茶：分数 **−2**，血量保持 **100**，飘字是 **`-2`**，消息却正确写着「抢食物 -2 分」。`checkFoodCollisions` 在负分分支调用了 `showDamage`。血条在小游戏里只是被 CSS 降到 0.35 透明度，还在。
- 对战模式里猫草/塑料袋改的是血（`resolveFoodEffectForCat`），和抢食物不是同一套结果。帮助弹层只写了回血/扣血，没写分数。

**13. 冷却和回能跟帧率绑在一起**

- 状态：**已证实（按 `update` 次数）**。`Cat.update` 里攻击/技能冷却每调用减 1，能量每调用 `+0.15`，都不乘 `deltaTime`。投射物位移则用了 `deltaTime`。
- 60 次 `update(16.67)` 能量 **+9**；120 次 `update(8.33)`（同样约 1 秒墙钟，若刷新率 120）能量 **+18**。攻击冷却 25、技能冷却 180 会同样减半。
- 猜测：没有在 120Hz 显示器上开一局。高刷机器上的手感会比 60Hz 快一倍，这个推断直接来自上面的计数方式。

**14. 玩家 2 的键盘和触屏都缺一截操作**

- 状态：**已证实（键位表和 DOM）**。茉莉攻击/防御/技能/暗器只绑定 `Numpad1/2/3/0`（`keyMappings`）。没有小键盘的笔记本打不了双人对战。
- 触屏按钮只有「攻击 / 防御 / 技能」，没有暗器。近战时 `attackTarget` 不会改发暗器，所以触屏近战无法主动丢飞镖。打耗子模式把攻击键转去 `fireProjectileTowardRat`，这条是通的。
- 人机模式显示的是单人触屏条，上面仍有「黑茶 | 茉莉」页签（`setupTouchControls`）。切到茉莉后，触摸输入和 `CatAI` 会同时叫 `moveCat('shiro')` / `attackCat('shiro')`。`handleKeyHold` 在人机时跳过了茉莉的键盘，触屏没有同样跳过。
- 猜测：真机上按钮是否互相遮挡没点过。键位缺失和页签抢控制是代码里就成立的。

**15. 默认照片立绘又大又被压成正方形**

- 状态：**已证实**。文件约 **2.8MB（2721×3100）** 和 **6.6MB（3024×4032）**。无头 Chrome 里能加载成功。`drawImageBody` 把图画进 `width === height` 的方框（约 160×布局缩放），竖构图会被压扁。每帧把 3000px 级位图缩进一百多像素的方框，移动端首帧和内存都会疼。
- 位置：`images/black-tea.png`、`images/white-Jasmine.png`，`js/cat.js` `drawImageBody`。

### P2

**16. README / PRD 和现行规则不是同一份**

- 状态：**已证实（对照阅读）**。帮助弹层和代码一致的部分，README 仍写着旧值：技能 50 能量、防御减伤 50%、茉莉攻击 20 / 防御 20（代码是 **22 / 18**）、神圣光芒会治疗。PRD 还写暗器 −10 能量；`fireProjectile` 不扣能量（远距离按 J 自动发射后能量仍是 100，已实测）。
- 这不是崩溃，但新玩家按 README 配能量和防御预期，会对不上手感。

**17. 静音按钮的字和状态是反的**

- 状态：**已证实**。初始 `audioManager.isMuted === false`，按钮文案是「开启音效」。`toggleMute` 在静音后把文案改成「关闭音效」。按钮读起来像动作，点下去却做相反的事。位置：`index.html` 底部脚本，`js/audio.js` `toggleMute`。

**18. 地上的食物几乎不淡出，然后突然消失**

- 状态：**已证实（公式）**。`foodAlphaMin = 0.92`，落地停留的后 30% 时间 alpha 也不会低于 0.92（`updateFood`）。玩家看不到「即将消失」。

**19. 直接打开 `index.html` 时，自定义照片清单不会生效**

- 状态：**代码可证，`file://` 未跑**。`PhotoSceneGallery.loadManifest` 用 `fetch`。`file://` 下 fetch 会失败并落入 `fallbackFiles`（五张内置图）。README 同时写「直接双击 index.html」和「改 manifest 就能加图」。HTTP 服务下 manifest 能读到（本次请求成功）。自定义文件名只在 HTTP 下可靠。

**20. 死代码和空系统会让下一次修改改错文件**

- 状态：**已证实**。全仓库没有调用：`BattleSystem.nextTurn`、`Cat.spawnFood` / `Cat.checkFoodCollision`（治疗量还是另一套 8–30，和 `game.js` 的 3–15 不同）、`renderObstacles`。`maps.js` 三张图的 `obstacles` 都是 `[]`，`resolveObstacleCollision` 因此从不生效。README「利用地形」没有碰撞体。`pendingRoundCheck` 只被赋值为 `false`。

## 设计或实现上不合理的地方

**规则写了三层，运行时只认最里面那层。** README、PRD、`index.html` 帮助、`Cat` 字段名互相打架（见 P1-6、P2-16）。帮助弹层在抢食物 / 打耗子时仍只讲三局两胜和回血食物。玩家打开「?」得到的是另一种模式的规则。

**「三局两胜」是实时血战，不是回合制。** `BattleSystem.turn` 和 `nextTurn` 不参与主循环。局数只在一方死亡动画结束后 +1。PRD 写「实时/回合混合」会让后面的人去接一个不存在的回合状态机。

**难度表描述的是抢食物 AI，不是对战 AI。** README 里的 48% / 56% / 90% 速度和犹豫概率只出现在 `getFoodModeAIParams`。对战 `CatAI` 用的是 800/400/85ms 和 60/40/11 帧冷却，并且不持续移动（P0-1）。大师「反应 85ms」只影响那一下 3px 挪步何时发生，不是 README 写的速度。

**放大地图用缩小整张画布来模拟，手感和 UI 一起坏。** 竹海/峡谷没有滚动摄像机。角色、暗器、近战 220px、技能 280px 都是世界像素，画到屏幕上要再除以 2 或 3，移动和攻击范围在视觉上变短，飘字和耗子还各错一次（P1-7、P1-8）。`NORMAL_MOVE_SPEED` 不乘 `mapScale`。地图按钮上的「场地 ×2 / ×3」玩家会理解成更大的战场，实际是更小的角色和更慢的跨越。

**普攻伤害被防御几乎减成个位数，技能又被写死暴击。** 黑茶攻击 25、茉莉防御 18：`25 × (0.8~1) − 18` 大约是 2–7，再叠加 15% 闪避。实测近战一击是 4。技能却强制 ×1.35，还会在够不着时白扣 35 能量。数值曲线鼓励「贴脸按技能」，普攻和暗器（伤害 2–6，还不扣能量）变成刮痧。防御 12%–40% 是随机的，玩家无法从举盾动画判断自己挡住了多少。

**打击、移动、食物、小游戏、输入全在 `game.js`（约 2760 行）和 `cat.js`（约 1710 行）。** 食物同时存在于 `game.foodItems` 和 `Cat.foodItems`。投射物命中在对战、打耗子、冲撞三条路径各写一遍，只有对战暗器传了格挡；冲撞和反噬没把 `damageKind` 设成可格挡类型。`lastAttackerId` 实际存的是上次打的目标 id，连击逻辑能工作，但名字会让下一次修改连击时改错。

**人机模式的身份不封闭。** AI 函数硬编码 `game.attackCat('shiro')`。触屏页签又能把「当前玩家」改成茉莉。双人、人机、触屏三套输入没有一个「这只猫本帧由谁驱动」的所有权。

**文案口吻和角色设定也不稳。** 黑茶设定是「只会喵」，低血量台词确实是喵；受击池却是「好痛！」「别打了！」（`kuroHitDialogs`）。茉莉技能叫治愈，画面是拍人。结果页胜利者用的是另一套内联 SVG（`createCatPreviewSVG`），不是刚打完的那只照片猫或战场猫。

## 美化与体验

截图观察（卡通、樱花、双人对战刚开局）：血条和名字贴在画面最上沿，角色头会顶进 HUD；两只几何猫和草地对比弱，脚底阴影很淡；中间的局数和左右上角的场景按钮很小。下面只写能在现有结构上做的一小步。

### 短期可做

1. **飘字跟屏幕坐标。** 为什么：竹海/峡谷上数字不在被打的那只猫头上，连击和背刺反馈等于没有。建议：`showDamage` / `showDodge` / `showDialog` 改为 `(cat.x - camera.x + width/2) * renderScale`，`top` 同样处理。樱花 scale=1 时结果不变。
2. **近战和暗器分开声音。** 为什么：现在打中也播投掷声，玩家会以为飞镖出手了（P1-3）。建议：`attackCat` 按 `attackResult.dodged` 和 `attackResult.damage` 分支；只有 `attackTarget` 真正 `fireProjectile` 时才播暗器声。
3. **把 HUD 让出角色头顶。** 为什么：开局两猫的头已经贴上血条，伤害数字再叠一层就全挤在顶部。建议：`.top-ui` 高度固定，`getPlayBounds().minY` 至少再加 40 世界像素，脚底椭圆阴影 alpha 从 0.1 提到约 0.35（`drawShadow`）。
4. **让隐身鼠真的淡，并给一个可追踪的轮廓。** 为什么：0.88 和 0.92 没有玩法差。建议：隐身 alpha 改为约 0.28–0.5，每 1.5 秒用 150ms 把描边拉回 0.9，避免完全找不到。只改 `minigames.js` 两个常数和 `drawRats`。
5. **食物消失前把 alpha 收到 0.2 以下。** 为什么：现在 92% 不透明然后没了，抢食物会觉得物品被吞。建议：`foodAlphaMin` 改为 `0.15`，停留最后 30% 线性降到它。负分不要调用 `showDamage`，改一个 `+2 / -2` 的分数飘字类名。
6. **静音按钮写成状态。** 为什么：现在「开启音效」表示声音开着，点下去却静音。建议：文案固定为 `音效：开` / `音效：关`，图标跟着 `isMuted` 走。
7. **触屏补一颗暗器，人机时拿掉茉莉页签。** 为什么：帮助教了 U / 小键盘 0，触屏没有等价键；人机切到茉莉会和 AI 抢同一只猫。建议：`.touch-actions` 加一个按钮调用现成的 `fireProjectileCat`；`gameMode === 'ai'` 时不要渲染 `[data-player=shiro]`。
8. **立绘先缩小再进仓库。** 为什么：6.6MB 的竖图被画成 160px 方块，加载和拉伸都可见。建议：导出最长边 512 的 WebP，`drawImageBody` 按原图宽高比算目标矩形，不要把宽高都设成 `this.width`。这一步不改战斗数值。

### 中期

1. **对战 AI 改成每帧追击，并复用抢食物那套速度系数。** 为什么：P0 不是「难度太高」，是决策被覆盖且每秒只走几个像素。建议：删掉 `makeDecision` 里无条件覆盖 `action` 的写法，用当前优先级最高的一项；`approach` 在 `update` 里按 `NORMAL_MOVE_SPEED * speedMult * (delta/16.67)` 持续移动。大师才使用 220–480 的暗器带，中等至少会走进 220。
2. **地图要么跟着相机走，要么把速度和攻击距离乘上 `mapScale`。** 为什么：×2/×3 现在是整图缩小。建议二选一：摄像机锁定两猫中点，视口保持 1:1；或维持缩图，但 `meleeRange`、暗器速度、`NORMAL_MOVE_SPEED` 乘 `mapScale`，飘字继续用短期第 1 条。不要两套都做一半。
3. **技能只保留一套名字和效果。** 为什么：治愈光波不治疗，AI 还按「防御技能」来放。建议：名字改成帮助里已有的「丢便便」「猫爪拍击」；`skillEffect` 改成 `'damage'`；空放时不扣能量，或扣了但在 `processSkill` 里写出「打空了」。若仍想要治疗，让茉莉在距离外走现成的 `heal_only` 分支，不要只改文案。
4. **冲撞一次只打一下，击退沿冲撞方向。** 为什么：现在方向和次数都不对（P0-2）。建议：`rushingCats[id].hit` 命中后置位；击退用 `direction` 把 `targetX/targetY` 推一个固定世界距离（例如 180），不要按中心点左右扔到屏幕另一边。
5. **给命中一个很短的停顿和爪痕。** 为什么：普攻只有 4 点左右，没有冲击帧时会像没打到。建议：`takeDamage` 时把双方 `animationTime` 停约 50ms，并在接触点画 3 条弧线，不要先上全屏技能遮罩（`showSkillEffect` 现在是盖住整个 `document.body` 的色块）。
6. **黑茶和茉莉的合成音错开音高。** 为什么：`audio.js` 的攻击、技能、对话音色接近，双人本地对战分不清是谁出手。建议：茉莉的振荡器频率乘 1.25，黑茶乘 0.85，只改 `playAttackSound` / `playSkillSound` 两个函数的频率常数。
7. **菜单把玩法类型放到首屏。** 为什么：「抢食物 / 打耗子」藏在「展开更多选项」里，首屏只有人机/双人和难度，和 README 的三种模式不一致。建议：把 `.playtype-section` 移出折叠面板，地图和触屏模式可以继续折叠。

## 建议的下一可玩里程碑

**里程碑 A：人机能在樱花庭院打完一小局。**  
只做四件事：对战 AI 每帧追击且远距离会丢暗器（P0-1）；冲撞单次命中并沿按键方向击退（P0-2）；技能打空不扣能量或有明确反馈（P1-4）；双倒地只平这一局、死亡动画期间不再吃伤害（P1-10）。完成标准：中等难度、双方都不操作以外的默认开局，茉莉在 20 秒内进入攻击或暗器距离，一小局能因血量归零结束并记下 1 胜，而不是干走到超时（当前没有超时，所以会一直走）。

**里程碑 B：三种模式用同一套反馈，放大地图不再错位。**  
飘字乘 `renderScale`（P1-7）；打耗子去掉第二次 scale，隐身 alpha 降到能看出差异（P1-8、P1-9）；反噬致死改为扣到 1 血或 1.5 秒无敌，不要让猫退出操作（P1-11）；抢食物负分改分数飘字（P1-12）；触屏加上暗器键（P1-14）；帮助弹层按 `playType` 换三节短规则。完成标准：竹海 + 打耗子时，耗子和猫同一比例，伤害/分数数字落在目标头顶；抢食物帮助不再教回血。

这两个里程碑都不需要新角色或新地图。P2 的文档漂移可以在改完规则后，用帮助弹层的句子回写 README，避免再出现第三份数值。
